1. Назначение и область применения

Настоящее Приложение фиксирует иерархическую систему визуальных стандартов экосистемы IMARCH. Цель документа — обеспечить унифицированное, верифицируемое и адаптивное визуальное исполнение всех выходных форматов, определённых Протоколом IPP: от слайдовых презентаций до полных печатных монографий.

Документ выполняет две функции:

  1. Официальная регистрация стандарта: Фиксация цветовых кодов, типографики, композиционных правил и стилей иллюстраций как части интеллектуального домена IMARCH LTD UK.
  2. Консультационный RAG-инструмент: Служит базой знаний для предварительной консультации заказчиков по выбору визуального стиля в зависимости от их целей и целевой аудитории.

Структура Приложения соответствует пяти официальным Annex Манифеста (RN-0043):

  • Annex A — Стандарт вёрстки (Раздел 2)
  • Annex B — Стандарт слайдовой инфографики (Раздел 3)
  • Annex C — Стандарт таблиц (Раздел 4)
  • Annex D — Стандарт иллюстративных баннеров (Раздел 5)
  • Annex E — Стандарт RAG-формата (Раздел 6)

 

 

2. Уровень 1: Стандарт вёрстки (Annex A)

ID стандарта: IMARCH-STD-VERSTKA-001

Данный уровень определяет, как упаковывается контент. Шесть стилей вёрстки (стили A-F) являются контейнерами, которые применяются к четырём типам вывода монографии:

  1. Формат презентации: Сжатие монографии в слайды.
  2. RAG-формат: Загрузка в базу знаний, фокус на типографику.
  3. Гибридный формат: Файл для загрузки в RAG-агенты, структурированная выжимка.
  4. Полный печатный формат: PDF-книга с полной вёрсткой.

3.2. Визуальные примеры слайдовых стилей

Шесть стилей оформления слайдовых презентаций: от строгого технологического до премиального издательского. Каждый стиль разработан для конкретной аудитории и задачи.

🖥️ S-1 · Dark Tech (технологический футуризм)

Строгий футуризм, хай-тек, безопасность, алгоритмы. Чувство сложности, защищённости и технологического превосходства.

⬜ S-2 · Clear White (академический минимализм)

Чистота, строгость, минимализм, научная достоверность. Ощущение объективности, прозрачности и академической честности.

🏢 S-3 · Corporate Light (деловой премиум)

Уверенность, прибыль, деловая эстетика, солидность. Чувство надёжности, статуса и финансовой стабильности.

🎬 S-4 · Media/Creative (кинематографичный)

Эмоции, премиум, креативность, кинематографичность. Ощущение роскоши, смелости и современности.

📊 S-5 · Vibrant Color-Coded (инженерный)

Инженерная динамика, кодирование данных, строгая структурированность. Ощущение системности, управляемости и технической точности.

📰 S-6 · Dark-Cream Editorial (издательский)

Издательская элитарность, глубокие тёмные тона, премиальная пресса. Чувство глубокой аналитики, интеллектуального веса и эксклюзивности.

4. Уровень 3: Стандарт таблиц (Annex C)

ID стандарта: IMARCH-STD-TABLES-001

Данный уровень определяет визуальное оформление табличных данных в документах экосистемы. Таблицы являются критическим элементом для представления структурированной информации: спецификаций, сравнительных характеристик, числовых данных, юридических и технических параметров.

Стандарт предусматривает двойную адаптацию: десктопную (широкие колонки, полноценная вёрстка) и мобильную (карточное представление, сворачиваемые блоки).

4.1. Принципы оформления таблиц
Принцип Описание
Читаемость Минимальный размер шрифта — 8pt, межстрочный интервал — 1.2em.
Иерархия Заголовки столбцов выделяются жирным шрифтом и цветом.
Адаптивность Ширина колонок автоматически подстраивается под контент.
Верификация Каждая таблица может быть привязана к хешу источника данных.

6. Уровень 5: Стандарт RAG-формата (Annex E)

ID стандарта: IMARCH-STD-RAG-001

Данный уровень определяет протокол структурирования текста для загрузки в AI-агентов (RAG-системы). Это «чистый» формат, который лишён визуального шума и предназначен исключительно для машинного извлечения знаний.

6.1. Принципы RAG-формата
Принцип Описание
Семантическая чистота Текст очищен от визуальных элементов (цвета, шрифты, макеты), сохраняется только смысловая структура.
Иерархическая структура Используются стандартные Markdown-элементы (#, ##, -, 1.).
Мета-тегирование Каждый блок данных содержит мета-информацию (ID документа, хеш, дата).
Верификационная привязка Каждый ответ AI-агента может быть отслежен до исходного блока через хеш.
6.2. Структура RAG-документа
# НАЗВАНИЕ ДОКУМЕНТА

**ID:** IMARCH-STD-XXX-001
**Хеш:** SHA-256: [hash]
**Дата публикации:** 2026-XX-XX

## 1. Введение

[Текст введения]

### 1.1. Подраздел

[Текст подраздела]

## 2. Основная часть

[Текст основной части]

### 2.1. Первый подраздел

[Текст подраздела]

#### 2.1.1. Детализация

[Текст детализации]

## 3. Заключение

[Текст заключения]
6.3. Правила форматирования
Элемент Правило
Заголовки Используются только #, ##, ###, ####. Без дополнительного форматирования.
Списки Только маркированные (-) и нумерованные (1.). Без вложенности более 3 уровней.
Таблицы Допускаются только простые таблицы (без объединения ячеек).
Цитаты Используется >. Блок цитаты должен содержать ссылку на источник.
Ссылки Только полные URL. Без коротких ссылок.
Выделение Только **жирный** и *курсив*. Без цветового выделения.
Код Используются блоки с указанием языка (```python).
6.4. Принцип «бесшумности» (Noise-Free Principle)

Текст в RAG-формате должен быть полностью «бесшумным» — то есть не содержать элементов, которые могут исказить семантику при машинной обработке:

  • ❌ Запрещены: Цвета, таблицы со сложной структурой, вложенные списки более 3 уровней, изображения.
  • ✅ Разрешены: Только текст, Markdown-разметка, мета-теги.
6.5. Верификационный протокол

Каждый RAG-документ содержит в заголовке:

  1. ID документа — уникальный идентификатор.
  2. Хеш SHA-256 — фиксация версии в реестре Verdictum.
  3. Дата публикации — временная метка.

Это обеспечивает возможность проверки ответов AI-агента на соответствие первоисточнику.

7. Методология консультации: Как выбрать стиль

Для предварительной консультации заказчика используется следующая логика, встроенная в RAG-агента.

7.1. Алгоритм подбора
  1. Определение выходного формата:
    • Если нужна презентация → выбираем Слайдовый стиль (S-1…S-6).
    • Если нужен PDF/книга → выбираем Стиль вёрстки (A…F) и Стиль таблиц (T-A…T-F).
    • Если нужна атмосфера для лонгрида/обложки → выбираем Иллюстративный стиль (I-1…I-12).
    • Если нужна загрузка в AI-агента → используем RAG-формат (Annex E).
  2. Анализ целевой аудитории:
Аудитория Рекомендуемый стиль вёрстки Рекомендуемый стиль слайдов Рекомендуемый иллюстративный стиль
Инженеры, DefenseTech, IT E (Vibrant Color-Coded) S-1 (Dark Tech) I-9 (Космо-Лаборатория)
Инвесторы, Бизнес, Топ-менеджмент B (Institutional Blue) S-3 (Corporate Light) I-5 (Вериктум-стайл)
Академическая среда, Наука, Гранты A (Monochrome Executive) S-2 (Clear White) I-4 (Академический романтизм)
Креативные индустрии, PR, СМИ C (Oat-Olive) S-4 (Media/Creative) I-7 (Бьюти-гламур) или I-2 (Антиквар-бутик)
Юридические структуры, Правительство D (Canonical Minimalist) S-1 (Dark Tech) I-6 (Мемори-стайл)
Культурные проекты, Издательства F (Dark-Cream Editorial) S-4 (Media/Creative) I-8 (Классическое Возрождение)

3. Фиксация решения: Все выбранные стили (вёрстка + слайды + таблицы + иллюстрации) фиксируются как часть проекта и привязываются к хешу в реестре Verdictum.
