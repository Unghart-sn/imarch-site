1. Purpose and Scope of Application

This Annex consolidates the hierarchical system of visual standards of the IMARCH ecosystem. The purpose of the document is to ensure unified, verifiable and adaptive visual execution of all output formats defined by the IPP Protocol: from slide presentations to complete printed monographs.

The document performs two functions:

  1. Official registration of the standard: Fixation of colour codes, typography, compositional rules and illustration styles as part of the intellectual domain of IMARCH LTD UK.
  2. Consultation RAG tool: It serves as a knowledge base for the preliminary consultation of clients on the selection of a visual style depending on their objectives and target audience.

The structure of the Annex corresponds to the five official Annexes of the Manifesto (RN-0043):

  • Annex A — Layout Standard (Section 2)
  • Annex B — Slide Infographics Standard (Section 3)
  • Annex C — Tables Standard (Section 4)
  • Annex D — Illustrative Banners Standard (Section 5)
  • Annex E — RAG Format Standard (Section 6)

 

 

2. Level 1: Layout Standard (Annex A)

Standard ID: IMARCH-STD-VERSTKA-001

This level defines how content is packaged. Six layout styles (styles A-F) are containers that are applied to four types of monograph output:

  1. Presentation format: Compression of the monograph into slides.
  2. RAG format: Loading into the knowledge base, with a focus on typography.
  3. Hybrid format: A file for loading into RAG agents, a structured summary.
  4. Full printed format: A PDF book with complete layout.

6. Level 5: RAG Format Standard (Annex E)

Standard ID: IMARCH-STD-RAG-001

This level defines the protocol for structuring text for loading into AI agents (RAG systems). This is a 'clean' format, devoid of visual noise, intended exclusively for machine knowledge extraction.

6.1. Principles of the RAG Format
Principle Description
Semantic purity The text is cleared of visual elements (colours, fonts, layouts); only the semantic structure is preserved.
Hierarchical structure Standard Markdown elements are used (#, ##, -, 1.).
Meta-tagging Each data block contains meta-information (document ID, hash, date).
Verification linkage Each response of the AI agent may be traced to the source block via its hash.
6.2. Structure of a RAG Document
# DOCUMENT TITLE

**ID:** IMARCH-STD-XXX-001
**Hash:** SHA-256: [hash]
**Date of publication:** 2026-XX-XX

## 1. Introduction

[Text of the introduction]

### 1.1. Subsection

[Text of the subsection]

## 2. Main Body

[Text of the main body]

### 2.1. First Subsection

[Text of the subsection]

#### 2.1.1. Detail

[Text of the detail]

## 3. Conclusion

[Text of the conclusion]
6.3. Formatting Rules
Element Rule
Headings Only #, ##, ###, #### are used. No additional formatting.
Lists Only bulleted (-) and numbered (1.). No nesting deeper than 3 levels.
Tables Only simple tables are permitted (without cell merging).
Quotations > is used. A quotation block must contain a reference to the source.
Links Full URLs only. No short links.
Emphasis Only **bold** and *italic*. No colour emphasis.
Code Blocks with language indication are used (```python).
6.4. The Noise-Free Principle

The text in the RAG format must be fully 'noise-free' — that is, it must not contain elements which may distort semantics during machine processing:

  • ❌ Prohibited: Colours, tables with complex structure, nested lists deeper than 3 levels, images.
  • ✅ Permitted: Text only, Markdown markup, meta-tags.
6.5. Verification Protocol

Each RAG document contains in its header:

  1. Document ID — a unique identifier.
  2. SHA-256 hash — fixation of the version in the Verdictum registry.
  3. Date of publication — a timestamp.

This ensures the possibility of verifying the responses of the AI agent against the primary source.

7. Consultation Methodology: How to Select a Style

For the preliminary consultation of a client, the following logic is used, embedded within the RAG agent.

7.1. Selection Algorithm
  1. Determination of the output format:
    • If a presentation is required → we select a Slide style (S-1…S-6).
    • If a PDF/book is required → we select a Layout style (A…F) and a Table style (T-A…T-F).
    • If atmosphere is required for a long read/cover → we select an Illustrative style (I-1…I-12).
    • If loading into an AI agent is required → we use the RAG format (Annex E).
  2. Analysis of the target audience:
Audience Recommended layout style Recommended slide style Recommended illustrative style
Engineers, DefenseTech, IT E (Vibrant Color-Coded) S-1 (Dark Tech) I-9 (Cosmo-Laboratory)
Investors, Business, Senior Management B (Institutional Blue) S-3 (Corporate Light) I-5 (Verdictum Style)
Academic Environment, Science, Grants A (Monochrome Executive) S-2 (Clear White) I-4 (Academic Romanticism)
Creative Industries, PR, Media C (Oat-Olive) S-4 (Media/Creative) I-7 (Beauty Glamour) or I-2 (Antiquarian Boutique)
Legal Structures, Government D (Canonical Minimalist) S-1 (Dark Tech) I-6 (Memorial Style)
Cultural Projects, Publishing Houses F (Dark-Cream Editorial) S-4 (Media/Creative) I-8 (Classical Renaissance)

3. Fixation of the decision: All selected styles (layout + slides + tables + illustrations) are fixed as part of the project and linked to a hash in the Verdictum registry.
