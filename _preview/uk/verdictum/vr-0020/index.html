1. Призначення та сфера застосування

Цей Додаток фіксує ієрархічну систему візуальних стандартів екосистеми IMARCH. Мета документа — забезпечити уніфіковане, верифіковане та адаптивне візуальне виконання всіх вихідних форматів, визначених Протоколом IPP: від слайдових презентацій до повних друкованих монографій.

Документ виконує дві функції:

  1. Офіційна реєстрація стандарту: Фіксація колірних кодів, типографіки, композиційних правил і стилів ілюстрацій як частини інтелектуального домену IMARCH LTD UK.
  2. Консультаційний RAG-інструмент: Слугує базою знань для попередньої консультації замовників щодо вибору візуального стилю залежно від їхніх цілей і цільової аудиторії.

Структура Додатка відповідає п’яти офіційним Annex Маніфесту (RN-0043):

  • Annex A — Стандарт верстки (Розділ 2)
  • Annex B — Стандарт слайдової інфографіки (Розділ 3)
  • Annex C — Стандарт таблиць (Розділ 4)
  • Annex D — Стандарт ілюстративних банерів (Розділ 5)
  • Annex E — Стандарт RAG-формату (Розділ 6)

 

 

2. Рівень 1: Стандарт верстки (Annex A)

ID стандарту: IMARCH-STD-VERSTKA-001

Цей рівень визначає, як пакується контент. Шість стилів верстки (стилі A-F) є контейнерами, які застосовуються до чотирьох типів виведення монографії:

  1. Формат презентації: Стиснення монографії у слайди.
  2. RAG-формат: Завантаження в базу знань, фокус на типографіку.
  3. Гібридний формат: Файл для завантаження в RAG-агенти, структурована вижимка.
  4. Повний друкований формат: PDF-книга з повною версткою.

3. Рівень 2: Стандарт слайдової інфографіки (Annex B)

ID стандарту: IMARCH-STD-SLIDES-001

Цей рівень визначає візуальне наповнення слайдів, банерів і рекламних матеріалів. На відміну від контейнерів (верстка), ці стилі визначають графічну естетику.

3.1. Таблиця стилів інфографіки

3.2. Візуальні приклади слайдових стилів

Шість стилів оформлення слайдових презентацій: від строгого технологічного до преміального видавничого. Кожен стиль розроблено для конкретної аудиторії та завдання.

🖥️ S-1 · Dark Tech (технологічний футуризм)

Строгий футуризм, хай-тек, безпека, алгоритми. Відчуття складності, захищеності та технологічної переваги.

⬜ S-2 · Clear White (академічний мінімалізм)

Чистота, строгість, мінімалізм, наукова достовірність. Відчуття об'єктивності, прозорості та академічної чесності.

🏢 S-3 · Corporate Light (діловий преміум)

Впевненість, прибуток, ділова естетика, солідність. Відчуття надійності, статусу та фінансової стабільності.

🎬 S-4 · Media/Creative (кінематографічний)

Емоції, преміум, креативність, кінематографічність. Відчуття розкоші, сміливості та сучасності.

📊 S-5 · Vibrant Color-Coded (інженерний)

Інженерна динаміка, кодування даних, строга структурованість. Відчуття системності, керованості та технічної точності.

📰 S-6 · Dark-Cream Editorial (видавничий)

Видавнича елітарність, глибокі темні тона, преміальна преса. Відчуття глибокої аналітики, інтелектуальної ваги та ексклюзивності.

4. Рівень 3: Стандарт таблиць (Annex C)

ID стандарту: IMARCH-STD-TABLES-001

Цей рівень визначає візуальне оформлення табличних даних у документах екосистеми. Таблиці є критичним елементом для представлення структурованої інформації: специфікацій, порівняльних характеристик, числових даних, юридичних і технічних параметрів.

Стандарт передбачає подвійну адаптацію: десктопну (широкі колонки, повноцінна верстка) та мобільну (карткове представлення, згортувані блоки).

6. Рівень 5: Стандарт RAG-формату (Annex E)

ID стандарту: IMARCH-STD-RAG-001

Цей рівень визначає протокол структурування тексту для завантаження в AI-агентів (RAG-системи). Це «чистий» формат, який позбавлений візуального шуму та призначений виключно для машинного вилучення знань.

6.1. Принципи RAG-формату
Принцип Опис
Семантична чистота Текст очищено від візуальних елементів (кольори, шрифти, макети), зберігається лише смислова структура.
Ієрархічна структура Використовуються стандартні Markdown-елементи (#, ##, -, 1.).
Мета-тегування Кожен блок даних містить мета-інформацію (ID документа, хеш, дата).
Верифікаційна прив'язка Кожна відповідь AI-агента може бути простежена до вихідного блоку через хеш.
6.2. Структура RAG-документа
# НАЗВА ДОКУМЕНТА

**ID:** IMARCH-STD-XXX-001
**Хеш:** SHA-256: [hash]
**Дата публікації:** 2026-XX-XX

## 1. Вступ

[Текст вступу]

### 1.1. Підрозділ

[Текст підрозділу]

## 2. Основна частина

[Текст основної частини]

### 2.1. Перший підрозділ

[Текст підрозділу]

#### 2.1.1. Деталізація

[Текст деталізації]

## 3. Висновок

[Текст висновку]
6.3. Правила форматування
Елемент Правило
Заголовки Використовуються тільки #, ##, ###, ####. Без додаткового форматування.
Списки Тільки марковані (-) та нумеровані (1.). Без вкладеності понад 3 рівні.
Таблиці Допускаються тільки прості таблиці (без об'єднання комірок).
Цитати Використовується >. Блок цитати повинен містити посилання на джерело.
Посилання Тільки повні URL. Без коротких посилань.
Виділення Тільки **жирний** та *курсив*. Без колірного виділення.
Код Використовуються блоки із зазначенням мови (```python).
6.4. Принцип «безшумності» (Noise-Free Principle)

Текст у RAG-форматі має бути повністю «безшумним» — тобто не містити елементів, які можуть викривити семантику під час машинного опрацювання:

  • ❌ Заборонено: Кольори, таблиці зі складною структурою, вкладені списки понад 3 рівні, зображення.
  • ✅ Дозволено: Тільки текст, Markdown-розмітка, мета-теги.
6.5. Верифікаційний протокол

Кожен RAG-документ містить у заголовку:

  1. ID документа — унікальний ідентифікатор.
  2. Хеш SHA-256 — фіксація версії в реєстрі Verdictum.
  3. Дата публікації — часова мітка.

Це забезпечує можливість перевірки відповідей AI-агента на відповідність першоджерелу.

7. Методологія консультації: Як вибрати стиль

Для попередньої консультації замовника використовується така логіка, вбудована в RAG-агента.

7.1. Алгоритм підбору
  1. Визначення вихідного формату:
    • Якщо потрібна презентація → вибираємо Слайдовий стиль (S-1…S-6).
    • Якщо потрібен PDF/книга → вибираємо Стиль верстки (A…F) і Стиль таблиць (T-A…T-F).
    • Якщо потрібна атмосфера для лонгриду/обкладинки → вибираємо Ілюстративний стиль (I-1…I-12).
    • Якщо потрібне завантаження в AI-агента → використовуємо RAG-формат (Annex E).
  2. Аналіз цільової аудиторії:
Аудиторія Рекомендований стиль верстки Рекомендований стиль слайдів Рекомендований ілюстративний стиль

Академічне середовище, Наука, Гранти A (Monochrome Executive) S-2 (Clear White) I-4 (Академічний романтизм)
Креативні індустрії, PR, ЗМІ C (Oat-Olive) S-4 (Media/Creative) I-7 (Б'юті-гламур) або I-2 (Антиквар-бутік)

3. Фіксація рішення: Усі вибрані стилі (верстка + слайди + таблиці + ілюстрації) фіксуються як частина проєкту та прив'язуються до хешу в реєстрі Verdictum.
